# macOS 桌面版实施方案

## 已确认的范围

使用 Tauri 2 包装现有 Flask、Alpine.js 与 daisyUI 界面，保留模型库、模型下载、文生图、参考图生图、队列、日志和画廊。仅支持 Apple Silicon macOS；不增加 Docker、代理服务或其他推理引擎。安装包内置 Python 与 mflux 依赖，模型权重首次使用时联网下载。

## 技术选择

- 构建继续使用 Node.js/npm，沿用现有依赖锁定；用户运行时不需要 Node.js、npm、uv 或 Python。
- Python 后端采用 PyInstaller 目录式打包，避免每次启动解压大型运行环境。
- Tauri 管理后端进程、启动状态与窗口；后端仅监听 `127.0.0.1` 的系统分配端口，并通过随机令牌建立会话。
- 桌面数据使用 macOS Application Support 目录，模型沿用 HF / ModelScope SDK 缓存；安装目录只存放程序资源。
- 以 `.app` 和 `.dmg` 直接分发，正式发布需要 Developer ID 签名与 Apple 公证。

## 实施顺序与验证

1. 拆分只读资源路径与可写数据路径，保持 Web 启动方式兼容。
2. 添加后端桌面入口、会话保护、父进程退出检测与冻结环境自检。
3. 添加 Tauri 外壳、启动失败重试、外部链接和图片窗口处理。
4. 添加可重复构建脚本、Python 打包配置和中文安装/发布文档。
5. 运行现有前后端回归、Rust 检查，构建实际安装包；验证冻结环境的模型导入、Metal 运算、页面/API 和进程退出。真实模型生图只使用本机已有权重，不额外下载大型模型。

## 完成标准

构建出的应用不依赖源码目录或开发虚拟环境；启动即可进入界面，没有模型时引导至模型库；退出不残留推理进程。验证结果须区分无签名本地构建与已签名、公证的正式发行版。
