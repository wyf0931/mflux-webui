# mflux 0.18.1 compatibility design

## Goal

Make the Web UI's mflux engine work with the locally installed mflux 0.18.1
release.  Version 0.18.1 is the only supported mflux version for this project.

## Dependency policy

The optional `mflux` extra will pin `mflux==0.18.1`.  The lockfile will be
regenerated from that declaration, so `uv sync --extra mflux` reproduces the
same version as the local uv tool.

## Engine boundary

`MfluxEngine` will invoke mflux's public `mflux-generate` command rather than
its private Python modules.  It will write to the engine-selected output path
and return the existing `GenerationResult` shape.  The Flask API, gallery, and
history schema stay unchanged.

The command receives the prompt, model, output path, width, height, seed,
steps, guidance, and quantization values.  A non-zero exit status returns a
clear generation error including mflux's diagnostic output.  The generated
file must exist before a result is recorded.

## Model and parameter mapping

The UI offers only model identifiers accepted by mflux 0.18.1: `schnell`,
`dev`, `krea-dev`, and `qwen`.  `qwen-image` is removed because it is not a
0.18.1 CLI model identifier.  Default dimensions, steps, guidance, seed, and
quantization retain their current UI semantics.  Width and height are clamped
to 256–2048 and rounded down to a multiple of 16; quantization is restricted
to mflux's supported 3, 4, 5, 6, or 8 bit options.

## Validation

Tests will mock command execution to verify command construction, successful
result handling, missing output handling, and CLI failure handling.  The
project will also run lock validation, Python compilation, import checks, and
Flask route smoke tests.  A full image generation is intentionally not part of
automated validation because it downloads models and requires Apple Silicon.
